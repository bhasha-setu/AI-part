# Eval set (DRAFT seed)

`answers.csv` is generated by `scripts/build_eval_set.py` from the course content. Every
row is a sentence the content already contains, labelled by a mechanical rule. **No label
is a human or native-speaker judgement**, and the set is a seed, not a benchmark.

| `label_source` | What the row is | Label |
|---|---|---|
| `content:model_answer` | the item's model answer, slots filled with the demo learner's values | correct |
| `content:accepted` | an accepted form with no slots | correct |
| `content:correction_example` | a listed error's corrected form (when not already a row) | correct |
| `content:common_error` | a listed error's example | surface_error + its id |
| `rule:empty_transcript` | `""` (silence or an STT miss) | off_topic |
| `definition:other_item_answer` | the next item's model answer, kept only if this item's rules don't accept it | off_topic |

Columns: `row_id, course_id, scenario_id, item_id, hint_level, transcript, label_verdict,
label_error_id, label_source`. `hint_level` is 0 for every seed row.

**Before trusting a number:** add real learner transcripts (STT output, not typed text)
with labels from a teacher, and keep a held-out split. With the stub judge the labels and
the judge share the content's rules, so stub agreement checks the plumbing only. The real
judge run is the measurement.

```bash
python3 scripts/build_eval_set.py                          # regenerate answers.csv
python3 -m pedagogy_server.eval_runner                     # stub judge
python3 -m pedagogy_server.eval_runner --judge gemini      # real judge: manual, uses quota
```

A test (`tests/test_server_eval.py`) fails if the committed CSV drifts from the generator.
If you add hand-labelled rows, put them in a separate file and pass `--answers`.
